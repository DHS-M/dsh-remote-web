DeepSeek Harness distribution

DSH Remote Web

Install the modified Harness from scratch and operate it through one browser interface. The product adds centralized open authority, host-backed remote settings, and a web-native configuration editor.

Authority model.

Every caller who can reach the service is treated as an authorized host user. Use a private network, firewall, or identity-aware proxy before exposing it beyond a trusted environment.

Install

curl -fsSL https://raw.githubusercontent.com/kenqtade/dsh-remote-web/main/install.sh -o install.sh
chmod +x install.sh
BUILD=1 ./install.sh "$HOME/dsh-remote-web"

Run the browser interface

cd "$HOME/dsh-remote-web"
pnpm dsh web --host 0.0.0.0 --open-authority --no-open

Open port 3080 in a trusted browser or forward it through a secure tunnel. For temporary testing, run cloudflared tunnel --url http://127.0.0.1:3080.

Remote capability matrix

CapabilityBrowser behavior
Settings and configurationIn-page YAML editor reads and writes the host-owned settings document.
Provider and plugin configurationHost-backed settings forms remain available to the remote browser.
Workspace selectionRemote filesystem browser lists directories and creates folders on the Harness host.
Sessions, approvals, questions, and resultsRendered in the web application through the shared RPC transport.
Desktop dialogsNot launched for the web editor; server desktop windows cannot be displayed in a remote browser.

Architecture

The patch changes the core connection and ApiProxy policy rather than adding exceptions to individual API routes. The browser receives an explicit server authority marker, and the settings layer chooses host-backed state from that marker even when the page is not loopback.

Source and reproducibility

The installer pins the official upstream commit recorded in UPSTREAM-COMMIT.txt and applies patches/open-authority-web-only.patch. The active base composition does not mount the DeepSeek provider; its source package remains available for intentional overlays.
